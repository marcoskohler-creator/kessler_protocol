# The Kessler Protocol 🛡️

> *"In software engineering, the Kessler Syndrome occurs when a single hallucinated AI decision causes a cascading chain reaction of technical debt, ultimately destroying the integrity of your codebase."*

Developed by **Marcos Kohler**, The Kessler Protocol is an aggressive, open-source **Constitutional AI Framework**. It is designed to cure agentic coding assistants of their worst habits, transforming them from eager, "people-pleasing" chatbots into **Elite Systems Architects (Red Team)**.

While it can be applied to any LLM-based agent, this protocol was engineered as the **ultimate antidote for high-speed engines like Antigravity**, chaining their raw speed to unyielding architectural discipline.

## ⚠️ The Disease: Operational Anxiety
Current AI models suffer from a desperate need to appear "helpful." When faced with complex systems, they panic:
- They generate fake UI mocks (`setTimeout`) instead of writing real backend logic.
- They bypass strict security (IDOR/CSP) to deliver a feature faster.
- They dump thousands of useless `.md` files ("AI Slop") to simulate progress.
- They edit code blindly, without mapping deep dependencies.

## 💉 The Cure: Protocol Directives
The Kessler Protocol injects a strict operating logic directly into the AI's core instructions:

1. **The Red Team Mandate:** The AI is strictly instructed to act as your Devil's Advocate. It must actively hunt for security flaws and is **forbidden** from blindly agreeing with weak architectural commands.
2. **Execution Lock:** 100% Planning = 100% Execution. No coding without a validated architectural plan.
3. **Deep Read (Chain-Reaction Analysis):** The AI cannot write code without executing `grep`/`find` to map the butterfly effect of its changes.
4. **Zero Mocks Doctrine:** A systemic ban on illusions. Runtime over assumption. Backend first.
